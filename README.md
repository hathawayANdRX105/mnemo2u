# mnemo2u

Memory / RAG library for coding harnesses: graph relations + vector facts over a
three-store design.

```
turso   (truth: documents, chunks, caches, reports)  ← commit point
turso   (graph: nodes, edges — second schema in the same engine)
lancedb (vector: entity/chunk ANN indexes)           ← derived, rebuildable
```

The truth layer is transactional; graph and vector indexes are derived from it
and can be rebuilt at any time. That split is what makes crash recovery and
index changes boring: write the truth last, rebuild the rest.

## Status

R1 — port of [nano-graphrag](https://github.com/gusye1234/nano-graphrag)
(`todo/01-nano-graphrag-port.md`) — implemented and exercised offline:

- chunking with token windows (`graph/chunk.rs`) — golden-parity fixtures
- entity/relation extraction with the gleaning loop (`graph/extract.rs`)
- merge with the reference's summary thresholds (`graph/merge.rs`)
- hierarchical community detection via `leiden-rs` (`graph/community.rs`)
- community reports (`graph/reports.rs`) — CSV context is byte-pinned against
  the reference's quoting rules (numbers bare, `format_row` fully quoted)
- query paths: local / global / naive (`query/`)
- insert & query facade with the reference commit order (`pipeline.rs`)
- LLM clients: OpenAI-compatible HTTP, cache with reference-parity args hash,
  deterministic mocks (`llm/`)
- stores: in-memory backends (tests), turso KV (truth), turso adjacency graph,
  lancedb vector indexes
- commit protocol: truth-first writes plus a repair queue that replays failed
  derived writes on the next flush (`store/repair.rs`)
- durable end-to-end smoke: ingest → restart over the same files → drop the
  vector index → rebuild it from truth → identical retrieval (`tests/durable_e2e.rs`)

Parity limitation worth knowing: the report-context bytes are pinned to the
*rules* read out of the reference, not to a live double-run (`.venv-ref` was
removed locally). Closing that needs a venv with `tiktoken` and a report golden
generator — tracked as the only open R1 acceptance item.

Why the graph lives in turso rather than a dedicated graph engine: the bundled
static build of kuzu 0.11.3 cannot link next to `turso_core` (duplicate simsimd
symbols, then undefined cxxbridge shim), and R1 needs exactly the `GraphStore`
surface — clustering runs over a snapshot. `todo/01-nano-graphrag-port.md`
records the evidence and the R2 re-entry condition.

Parity is checked against the reference implementation: fixtures under
`tests/fixtures/` are generated by scripts in `scripts/` that run the
reference Python code (see `todo/refs/nano-graphrag`, cloned locally, not
committed).

## Development

Requires a stable Rust toolchain. `lancedb` needs `protoc` at build time
(`apt install protobuf-compiler`, as CI does).

```bash
cargo fmt --all -- --check
cargo check --all-targets
cargo clippy --all-targets -- -D warnings
```

Tests run in CI (`.github/workflows/ci.yml`), including the golden-parity
suites; they need no network and no model downloads.

Regenerate the golden fixtures (needs a venv with `tiktoken` in `.venv-ref/`):

```bash
.venv-ref/bin/python scripts/gen_chunks.py > tests/fixtures/chunk_golden.json
.venv-ref/bin/python scripts/gen_extraction.py > tests/fixtures/extraction_golden.json
.venv-ref/bin/python scripts/gen_hash.py > tests/fixtures/hash_golden.json
.venv-ref/bin/python scripts/gen_merge.py > tests/fixtures/merge_golden.json
.venv-ref/bin/python scripts/gen_prompts.py   # src/graph/prompts/*.txt
```
