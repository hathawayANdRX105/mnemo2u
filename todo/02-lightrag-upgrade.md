## R2 相对 R1 改什么（LightRAG 的核心增量）

1. **不重算社区**：R1 沿袭 nano-graphrag 语义——每次 insert 重算社区与报告；R2 改为**增量更新**——新文档只更新受影响实体/关系，社区延后/按需重算（LightRAG 的关键优化之一）。
2. **双层检索**：查询关键词分「低层（具体实体/术语）」与「高层（主题/概念）」；低层走实体向量、高层走关系与主题标签——替代 R1 的单层召回。
3. **关键词标签**：抽取时给实体与关系生成 keyword 属性（`relationship_keywords`），供高层匹配与过滤。
4. **选择性删除**：删除文档时按来源引用清理实体/关系/chunk/向量（R1 只标注）。
5. **合并升级**：跨文档实体/关系归一——embedding 相似度预筛 + LLM 判定（LightRAG 去重逻辑），替代 R1 的名称精确合并。
6. **成本**：高价值 chunk 才做 LLM 抽取（本地评分预筛，KET-RAG 式）；LLM 缓存键、抽取用非思考小模型。

## 功能清单（本阶段实现什么）

- F1 增量插入：`insert(doc)` 不触碰未受影响社区；社区重算按需（阈值/手动）。
- F2 双层关键词：抽取产 `entity_keywords`/`relationship_keywords`（LLM）；查询侧产 low/high 双层词。
- F3 双层召回：low → 实体向量/图邻域；high → 关系向量/主题标签；两路结果融合（完整多臂融合与预算在 R3）。
- F4 跨文档合并：相似实体/关系归一（embedding 预筛 + LLM 判定），保留合并审计。
- F5 选择性删除：`delete(doc_id)` 级联清理可查证（chunk→向量→边→悬空实体判定）。
- F6 成本控制：价值评分（信息密度启发式）低于阈值的 chunk 零 LLM 调用；抽取模型档位配置（建库快速档/查询精确档分离）。
- F7 历史会话接缝：会话 closed turn 作为 doc 流插入，chunk 携带 `conversation_id`/时间戳（R3 时间臂的前置数据基础）。
- F8 写治理与水位：去重（T4）之外的冲突双保留（`contradicts` 不覆盖）、tombstone 拦截（操作集定义在 R5，检查点在此）；`organized_through` 水位与 turso 提交**同事务**，重放幂等。
